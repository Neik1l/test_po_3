# Практическая работа № 3 — вариант 85

**Предмет:** Тестирование и верификация ПО  
**Продукт:** флэш-карты для изучения языков.  
**Методы:** TDD, ATDD, BDD, SDD.

## Возможности

- Добавить и изменить языковую карточку (слово, перевод, язык).
- Посмотреть список карточек.
- Пройти сессию; порядок вопросов соответствует порядку добавления.
- Посмотреть правильные/неправильные ответы и точность в процентах.
- Сохранить карточки и историю сессий в JSON между запусками.
- Автоматически проверить программные требования.

## Установка и запуск в VS Code (Windows)

1. Скачайте или распакуйте проект в отдельную папку.
2. В VS Code выберите **File → Open Folder** и эту папку.
3. Убедитесь, что установлен Python 3.10+ (в терминале: `py --version`).
4. В терминале выполните `py main.py` либо `python main.py`.
5. Файл `flashcards_data.json` создаётся при первом добавлении или завершении сессии.

Пример запуска с собственным файлом данных:

```powershell
py main.py --data "my_words.json"
```

## Автоматическое тестирование

Сторонние библиотеки не нужны (используется стандартный `unittest`).

```powershell
py -m unittest discover -s tests -p "test_*.py" -v
```

На macOS/Linux:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

**Группы тестов:**

| Метод | Файл | Назначение |
| --- | --- | --- |
| TDD | `tests/test_tdd_cards.py` | создание, редактирование и валидация карточек |
| ATDD | `tests/test_atdd_acceptance.py` | пользовательские критерии приёмки |
| BDD | `features/study.feature`, `tests/test_bdd_scenarios.py` | Given/When/Then и автоматизация сценариев |
| SDD | `tests/test_sdd_examples.py` | таблица конкретных входов и ожидаемых результатов |
| Регрессия | `tests/test_sessions.py`, `tests/test_storage.py` | сессии, статистика, JSON |

Для BDD предусмотрен **учебный минимальный исполнитель Gherkin**, поддерживающий только использованные в проекте операторы `Given`, `When`, `Then`, `And`. Внешний фреймворк `behave` не нужен.

## RED → GREEN → REFACTOR и честная история Git

TDD предполагает тест **до** рабочего кода. Если весь готовый проект копируется одним действием, последующее разделение его на коммиты не доказывает, что тесты действительно написаны первыми. Для доказательной истории:

1. Добавьте и сохраните коммит только с тестами карточек (`test_tdd_cards.py`) — при запуске тесты должны падать, если реализации ещё нет (**RED**).
2. Напишите модуль `models.py` и минимальную реализацию методов из `trainer.py`; убедитесь, что тесты карточек проходят (**GREEN**) и сделайте коммит.
3. Измените структуру кода без изменений поведения, ещё раз запустите тесты (**REFACTOR**) и сделайте коммит.
4. Аналогично последовательно добавьте ATDD, BDD, SDD и расширения. Не утверждайте, что у вас был этап RED, если вы на самом деле коммитили полностью готовую реализацию.

Подробнее о коммитах: `docs/План_коммитов.md`.

## Ограничения

Локальное консольное приложение: без аккаунтов, облачной синхронизации и распределённой работы. Сравнение ответов игнорирует регистр и пробелы по краям; опечатки и альтернативные переводы считаются неправильными.
